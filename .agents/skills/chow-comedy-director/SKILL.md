# 无厘头喜剧导演研究

## 执行流程

1. 确认片段路径、来源名称、研究问题与原片时间基准。只处理用户提供或获准使用的素材；没有素材时准备模板，不臆造电影证据。默认在 Codex 云端现有仓库工作，不要求用户本地安装。
2. 阅读 [分析规程](references/analysis-protocol.md)。先以正常速度观看含声音的片段，再分别检查静音画面和声音。只看过关键帧时明确标记表演、声音与节奏为“未核实”；如当前工具不能连续观看或听音，保留这些字段待复核。
3. 运行 `python3 <skill目录>/scripts/preprocess.py <视频路径> --output <新的分析目录>`。需要 Python 3.10+、FFmpeg/ffprobe 6+ 与 libx264。不要覆盖原片。命令失败时先检查 stderr；失败目录保留用于诊断，改用新目录重试。
4. 读取输出 `manifest.json`、`frame-map.csv` 和 `source.ffprobe.json`。以原始 PTS 秒数定位证据，以逐帧映射回查源片。不要把片段相对秒数、原片 PTS、SMPTE 时间码混用。原始 timecode 标签按原样保存在 manifest；不自动推算丢帧时间码。
5. 人工复核切点候选和每镜头中点关键帧；检查渐变、闪光、遮挡、快速运动导致的误报及漏报。修正 `shots.csv` 并记录边界版本；不要将候选表称为已确认分镜。跨切点笑点应关联多个镜头。
6. 填写 `shots.csv`、`comedy-beats.csv` 与 `analysis-report.md`，使用 [节拍字段说明](references/analysis-protocol.md)。分开记录可观察事实、解释假设和信心；对白只引用识别机制所需的最短部分，优先概述。不要用故事梗概代替视听分析。
7. 按 [方法库结构](references/method-library.schema.json) 填写 [方法模板](assets/method-card.json)，每条方法写成“条件—操作—观众预期变化—风险—验证”。运行 `scripts/validate_method.py <方法.json>` 检查数据结构。未复核的证据不得标成 confirmed。
8. 输出分析表、节拍链、方法条目与局限。原创迁移时更换人物关系、场景、目标、道具和动作因果，保留抽象机制；通过对照实验测试停顿、反应镜头或声画错位的作用，不复刻台词、动作序列、角色造型或标志性桥段。不生成图片或视频成品。

## 交付约定

- 每项结论关联来源标识、源片时间区间、镜头 ID 和复核状态；未知项写“未核实”。
- 六个维度都要检查：镜头、表演、调度、笑点、声音、剪辑。建立“铺垫→预期→偏移→兑现→反应/余波”的节拍链，不强行把所有片段套成完整链。
- 明确区分技法有效性的假说与经观众实验支持的结论。单个例子只形成候选方法。
- 预处理仅生成研究用代理和关键帧；素材和派生文件保留在忽略的工作目录，不提交电影媒体。
